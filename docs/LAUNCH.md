# Запуск Telegram-бота The Tender у production

Покроковий план запуску основного бота @ProzorroSale_bot. Ролі:
- **Власник** — власник продукту (GitHub, BotFather, адмінка);
- **Девопс** — сервер, `.env`, nginx, резервні копії;
- **API** — розробник The Tender.

Тестовий бот @TgtestTT_bot (`/opt/thetender-telegram/test`) і основний (`/opt/thetender-telegram/prod`) — це окремі
копії з окремими базами даних. Користувачі тестового бота в основному боті реєструються заново. Так і має бути.

---

## 1. Що потрібно до запуску

### 1.1. The Tender (API)
- [ ] Повторна відправка вебхука кожні 300 с до відповіді 2xx працює, у тому числі після перезапуску майданчика.
- [ ] Підтверджено, що `auction_data.number` унікальний і незмінний. Бот за ним відсіює дублікати сповіщень.
- [ ] Фільтр `start_price_type=eng/hol` (англійський / голландський аукціон) повертає результати.
- [ ] Видано **окремий production-ключ** Telegram-бота. Девопсу його передають особисто, не в чаті.
- [ ] Відповідь на питання: моніторинги, створені тестовим ботом з поточним ключем, будуть видні з новим ключем?
  Якщо **так**, їх треба видалити до запуску (див. 1.4).

### 1.2. Telegram (Власник)
- [ ] @BotFather → @ProzorroSale_bot → **API Token → Revoke current token**. Старий токен колись потрапив у чат, тож має бути
  відкликаний. Новий токен передати девопсу особисто.
- [ ] @BotFather → @ProzorroSale_bot → **Login Widget** → домен `tg.thetender.com.ua`. Без цього не працює вхід в адмінку.
- [ ] За бажанням: назва, опис («What can this bot do?»), аватар бота в BotFather.

### 1.3. Сервер (Девопс)
- [ ] DNS `tg.thetender.com.ua` вказує на 159.200.246.70, налаштовано nginx і сертифікат. Приклад конфігурації:
  `docker/nginx/thetender-telegram.conf.example`. Для `/thetender/webhook` журнал запитів вимкнено, бо в адресі є ключ.
- [ ] `/opt/thetender-telegram/prod/.env`:

  ```
  ENVIRONMENT=prod
  BOT_MODE=webhook
  APP_PORT=8082
  TELEGRAM_BOT_TOKEN=<новий токен @ProzorroSale_bot>
  PUBLIC_BASE_URL=https://tg.thetender.com.ua
  TELEGRAM_WEBHOOK_SECRET=<випадковий рядок, 32+ символи>
  LINK_SIGNING_SECRET=<інший випадковий рядок, 32+ символи>
  THETENDER_BASE_URL=https://thetender.com.ua
  THETENDER_API_KEY=<production-ключ від The Tender>
  THETENDER_MOCK=false
  # ALLOW_PRODUCTION_API_IN_TEST не потрібен у prod
  ```
  Випадковий рядок можна згенерувати командою `openssl rand -hex 32`.
- [ ] Щоденна резервна копія бази prod (`scripts/backup_db.sh`) і **одна перевірена** спроба відновлення (`scripts/restore_db.sh`).
- [ ] Моніторинг доступності `https://tg.thetender.com.ua/health` (наприклад, UptimeRobot чи подібний), сповіщення при збої.
- [ ] З сервера доступний Telegram: `curl -sS https://api.telegram.org` відповідає.
- [ ] Автодеплой у prod приймає **лише теги** `vX.Y.Z`, `origin/main` не дозволено.

### 1.4. Якщо тестові моніторинги видно з новим ключем
Найпростіше: до запуску кожен тестувальник у тестовому боті видаляє свої моніторинги
(«🔔 Мої моніторинги» → «🗑 Видалити»). Або адмін тестового бота виконує для тестувальників
«Видалити персональні дані»: бот сам видалить їхні моніторинги на сайті.

## 2. День запуску

1. **Власник:** GitHub → Releases → *Draft a new release* → тег `v1.0.0`, Target `main` → *Publish release*.
2. **Власник:** Actions → Deploy → *Run workflow*: `main` / `prod` / `v1.0.0`. Результат має бути ✅.
3. Відкрити `https://tg.thetender.com.ua/health`. Очікується `"environment":"prod","version":"v1.0.0"`.
4. **Власник:** у Telegram відкрити @ProzorroSale_bot → `/start` → «Поділитися телефоном».
5. **Девопс:** призначити першого адміністратора:
   ```
   cd /opt/thetender-telegram/prod
   docker compose -p tg-prod exec app python -m app.cli grant-admin --phone +380663524080
   ```
6. **Власник:** увійти в `https://tg.thetender.com.ua/admin` і заповнити:
   - Налаштування → **Юридичні документи**: Умови й Політика (посилання або файл);
   - Налаштування → **Тексти бота**: FAQ, «Про Prozorro.Продажі», «Тарифи»;
   - **Менеджери** (Користувачі → «Зробити менеджером»). Людина має спершу зареєструватися в боті;
   - за потреби інших **адміністраторів** (запрошення).
7. **API:** прописати адресу вебхука **`https://tg.thetender.com.ua/thetender/webhook`** (з `?auth=<prod-ключ>`).
8. Перевірка, приблизно 15 хвилин:
   - [ ] пошук знаходить аукціони, посилання ведуть на thetender.com.ua;
   - [ ] створити моніторинг з широкими параметрами, дочекатися сповіщення про новий аукціон;
   - [ ] замовити консультацію: менеджер отримує картку й бере її в роботу;
   - [ ] адмінка: «Огляд» показує реєстрації та пошуки;
   - [ ] **Viber-бот працює як раніше** (пошук, моніторинги, сповіщення).

## 3. Після запуску
- **Тестовий бот** лишається для перевірки нових версій. Щоб тести не впливали на бойовий сайт, переведіть test назад на
  sandbox: `THETENDER_BASE_URL=https://sandbox.mxuser.com` + sandbox-ключ, приберіть `ALLOW_PRODUCTION_API_IN_TEST`.
- **Нові версії:** зміни → тестовий бот (автоматично після merge в `main`) → перевірка → реліз `v1.0.1` → Deploy `prod`.
- **Відкат:** Deploy `prod` з попереднім тегом (наприклад, `v1.0.0`). Міграції бази в нових версіях лише додають
  таблиці/поля, тож попередня версія з ними працює.
- **Технічні сповіщення:** адміністратори з увімкненими «системними сповіщеннями» отримують у Telegram повідомлення, якщо
  The Tender відхиляє ключ, вебхук приходить з неправильним ключем або виникає збій обробки (не частіше разу на годину
  для кожного типу).
