API майданчика The Tender для Viber- та Telegram-ботів
(зведений опис, 16.10.2026 - замість окремих документів по Telegram-боту і по балансоутримувачу)

ОБидва боти працюють з одним API. Адреси і параметри запитів однакові, відрізняється тільки ключ: по ключу майданчик сам визначає, від якого бота прийшов запит, ніяких додаткових параметрів передавати не треба. Боти один одного не бачать - моніторинги, адреса вебхука і ключ у кожного свої. Ключі передам окремо

Базова адреса: https://thetender.com.ua
Відповіді у форматі JSON.


1. Авторизація

Ключ передається параметром auth в адресі або заголовком Authorization. Без ключа чи з невірним ключем повертається 403.
Ключ Viber і ключ Telegram незалежні: один можна змінити або відкликати, на другий це не вплине.


2. Ендпоінти

GET     /rest/categories - категорії для бота
GET     /rest/auctions - пошук аукціонів, на які зараз приймаються заяви
GET     /rest/monitoring?user_id=... - моніторинги користувача
POST    /rest/monitoring/create - створити моніторинг
PUT     /rest/monitoring/update?id=... - змінити моніторинг
DELETE  /rest/monitoring/delete?id=... - видалити моніторинг
POST    /rest/set_webhook - задати адресу вебхука свого бота (п. 6)


3. Категорії

GET /rest/categories повертає список [{id, name}]. Список один для обох ботів: які категорії доступні, визначається в адмінці галочкою "Пошук у Viber/Telegram" у налаштуваннях категорії. Без галочки категорії немає у списку, по ній не працює пошук і не приходять сповіщення по моніторингах.


4. Пошук аукціонів

GET /rest/auctions - у видачі тільки аукціони, на які зараз приймаються заяви (поле status у всіх однакове - "Прийняття заяв на участь"). Усі параметри необов'язкові:
- auction_type - sale (продаж) або rent (оренда)
- start_price_type - eng (англійський аукціон) або hol (голландський)
- category - назва категорії зі списку /rest/categories
- region - область, одна або декілька (п. 7)
- city - населений пункт
- keywords - ключові слова
- customer_name - ЄДРПОУ або назва організатора
- balance_holder - ЄДРПОУ або назва балансоутримувача (п. 8)
- min_price, max_price - стартова ціна, грн
- area_unit (ha. або sq.m.), min_area, max_area - площа
- page, pagesize - номер сторінки та кількість на сторінці (до 100, типово 50)

Якщо значення параметра невірне (невідома категорія, start_price_type не зі списку і т.п.), повертається порожній список.

У відповіді: itemsCount, pagesCount, page, pagesize, nextPageLink (адреса наступної сторінки або null) і data - список аукціонів з полями:
name, number, companyName (організатор), auctionStart, status, start_price_type, auction_type, price, balance_holder, url
balance_holder - {"name": "...", "edrpou": "..."} або null, якщо балансоутримувача немає.
Посилання у полі url йдуть з міткою utm_source=viber або utm_source=telegram, залежно від бота.


5. Моніторинги

user_id - id користувача у боті (для Telegram - числовий id, наприклад 123456789). Зберігаємо його рядком, до 255 символів. Моніторинги Viber і Telegram зберігаються окремо: з ключем Viber видно і можна змінювати тільки моніторинги Viber, з ключем Telegram - тільки Telegram. Якщо user_id у двох ботах випадково співпаде, це все одно різні користувачі.

Обов'язкові поля - user_id та name (назва моніторингу), далі ті самі фільтри, що й у пошуку: auction_type, start_price_type, category, region, city, keywords, customer_name, balance_holder, min_price, max_price, area_unit, min_area, max_area. Потрібен хоча б один фільтр; для min_area і max_area обов'язковий area_unit. На користувача - до 200 моніторингів.
Дані можна передавати у JSON (Content-Type: application/json) або звичайною формою; поля - плоско або вкладеними в об'єкт monitoring (як у відповіді).
ПРи зміні (update) передаються всі поля, включно з user_id і name - не передані очищуються.
id в адресах update та delete - це id моніторингу (приходить у відповіді на створення та у списку). Для Viber замість id можна передати user_id, тоді береться перший моніторинг цього користувача (стара поведінка).
У відповіді на створення та зміну: saved (true/false), errors, data. На видалення: deleted. Якщо моніторинг не знайдено або він належить іншому боту - 404.

Приклад створення:

POST /rest/monitoring/create
{
  "user_id": "123456789",
  "name": "Оренда, Київ та область",
  "auction_type": "rent",
  "region": "Київ,Київська область",
  "balance_holder": "міністерство оборони"
}

Відповідь:

{
  "saved": true,
  "errors": [],
  "data": {
    "id": 15,
    "user_id": "123456789",
    "monitoring": {
      "name": "Оренда, Київ та область",
      "auction_type": "rent",
      "start_price_type": null,
      "category": null,
      "region": "Київ,Київська область",
      "city": null,
      "keywords": null,
      "customer_name": null,
      "balance_holder": "міністерство оборони",
      "min_price": null,
      "max_price": null,
      "area_unit": null,
      "min_area": null,
      "max_area": null
    }
  }
}

У такому ж вигляді (id, user_id, monitoring) моніторинги приходять і у списку GET /rest/monitoring?user_id=...

Моніторинг спрацьовує на новий аукціон, якщо збігаються всі задані у ньому фільтри: keywords - одне або декілька слів через кому, досить збігу одного з них у назві чи описі; customer_name - входження у назву організатора; region і city - по адресах лотів; ціна і площа - по стартовій ціні та площі лотів.


6. Вебхук про новий аукціон

Адресу вебхука кожен бот задає сам, своїм ключем:

POST /rest/set_webhook
{
  "address": "https://bot.example.com/thetender/webhook"
}

address можна передати у JSON або звичайною формою. Адреса має починатися з https:// і бути без параметрів - ключ ми дописуємо самі (див. нижче).

Відповідь:

{
  "saved": true,
  "address": "https://bot.example.com/thetender/webhook"
}

Якщо адреса не підходить або її не передано - 400, причина у полі message.
Нова адреса діє одразу, з наступної відправки (у тому числі для подій, які чекають повторної спроби). Запит можна викликати скільки завгодно разів, наприклад при кожному старті бота.
Ключ Viber задає тільки адресу Viber-бота, ключ Telegram - тільки Telegram-бота. Для Viber, поки адресу через set_webhook не задано, працює адреса, яка прописана у нас зараз; для Telegram без заданої адреси запити не відправляються.

Коли на майданчику з'являється новий аукціон, який підходить під моніторинги бота, ми відправляємо POST на адресу цього бота: <адреса>?auth=<ключ цього бота>, тіло у форматі JSON:

{
  "event_type": "new_auction",
  "auction_data": { ... ті самі поля, що у пошуку, url з міткою цього бота ... },
  "users": [ { "<user_id>": "<назва моніторингу>" } ],
  "event_id": 12345
}

На кожен аукціон - один запит на бота, у users перелічені тільки користувачі цього бота, у яких спрацював моніторинг. Якщо у користувача спрацювало кілька моніторингів, він буде у списку один раз.
event_id - номер події на майданчику, є тільки у вебхуку Telegram; при повторній відправці він той самий, по ньому можна відсіювати дублі. Тіло вебхука Viber не змінювалось.

Доставка: чекаємо відповідь 2xx (від Telegram-бота - протягом 10 секунд, для Viber окремого обмеження немає). Якщо відповіді немає (таймаут, сервер недоступний або код не 2xx), подія зберігаєтсья і відправка повторюється: ще дві спроби одразу, далі приблизно кожні 5 хвилин, поки не отримаємо 2xx. Повторюється той самий запит (ті самі auction_data, users та event_id).
Історію відправок видно в адмінці, розділ "Статистика викликів ботів (Viber, Telegram)", там є фільтр по боту. Недоставлену подію там же можна відправити повторно вручну.


7. Області (region)

І в пошуку, і в моніторингах у region можна передати одну або декілька областей:
- одним рядком через кому: region=Київ,Львівська область
- масивом: region[]=Київ&region[]=Львівська область (у JSON - "region": ["Київ", "Львівська область"])

Аукціон підходить, якщо хоча б один лот знаходиться в одній з указаних областей. У відповідях по моніторингах region завжди повертається рядком через кому.

8. Балансоутримувач (balance_holder)

ЄДРПОУ або назва, до 255 символів. Кожне слово має бути в назві чи коді, порядок і регістр не важливі. Балансоутримувач є лише в оренді держмайна, малій і великій приватизації, в інших аукціонах balance_holder у видачі - null. Комбінується з рештою параметрів:

/rest/auctions?balance_holder=00034022
/rest/auctions?balance_holder=міністерство оборони&region=Київська область

У моніторингах правила ті самі: сповіщення приходить, лише коли балансоутримувач аукціону підходить. При update поле треба передавати щоразу, інакше очиститься.
