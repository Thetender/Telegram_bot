API майданчика The Tender для Telegram-ботів і порталу InfoPilot
(актуальна версія від 22.10.2026: пошук і вебхуки також повертають аукціони в статусі «Редагування доступне» і продаж без аукціону)

Telegram-боти і портал InfoPilot працюють з тим самим API, що і Viber-бот. Адреси та параметри запитів ті самі, відрізняється тільки ключ. Кожен ключ - окремий клієнт зі своїми моніторингами і своєю адресою вебхука, клієнти один одного не бачать. Для Viber-бота нічого не змінилось.

Базова адреса для всіх: https://thetender.com.ua


1. Ключі та авторизація

Ключі видаються окремо для кожного клієнта:
- Telegram, основний бот
- Telegram, тестовий бот
- InfoPilot - один ключ на всіх клієнтів порталу (nika, nika-test і т.д.)

Тестовий бот працює з тим самим майданчиком і реальними аукціонами, але моніторинги і вебхуки в нього свої, тому тестування не впливає на основного бота.
Ключ передається параметром auth в адресі або заголовком Authorization. Без ключа чи з невірним ключем повертається 403. Відповіді у форматі JSON.
По ключу майданчик сам визначає, від кого прийшов запит, додаткових параметрів передавати не треба.
Будь-який ключ можна змінити або відкликати, на інших клієнтів це не вплине.
Обмеження за IP-адресою немає, доступ лише за ключем. Кількість запитів - до 5 на секунду з однієї IP-адреси (короткий сплеск до 20), понад це сервер відповідає 429
Ключі передам окремо.


2. Ендпоінти

GET     /rest/categories - список категорій
GET     /rest/auctions - пошук аукціонів, на які зараз приймаються заяви
GET     /rest/monitoring?user_id=... - моніторинги користувача
POST    /rest/monitoring/create - створити моніторинг
PUT     /rest/monitoring/update?id=... - змінити моніторинг
DELETE  /rest/monitoring/delete?id=... - видалити моніторинг
POST    /rest/set_webhook - задати адресу вебхука (п. 8)


3. Користувачі (user_id)

user_id - рядок до 255 символів. У Telegram-ботах це Telegram id (число, наприклад 123456789), у InfoPilot можна використовувати будь-який текстовий ідентифікатор, наприклад nika-12.
Моніторинги кожного ключа зберігаються окремо: з ключем видно і можна змінювати тільки свої моніторинги. Якщо user_id у двох клієнтів співпаде - це все одно різні користувачі, тому окремий діапазон ідентифікаторів не потрібен.
У InfoPilot усі клієнти порталу працюють з одним ключем, тому user_id варто робити з префіксом клієнта (nika-12, nika-test-3), щоб вони не перетиналися. Новий клієнт порталу нічого не потребує з нашого боку - достатньо створювати його моніторинги з його префіксом і його адресою вебхука (п. 6).


4. Пошук аукціонів

Повертаються аукціони від моменту публікації: у періоді редагування (статус «Редагування доступне») і ті, на які зараз приймаються заяви («Прийняття заяв на участь»). Усі параметри необов'язкові:
- auction_type - sale (продаж) або rent (оренда)
- start_price_type - eng (англійський аукціон) або hol (голландський)
- category - назва категорії зі списку /rest/categories
- region - регіон, один або декілька (див. п. 5)
- city - населений пункт
- keywords - ключові слова
- customer_name - назва або код організатора
- balance_holder - назва або код ЄДРПОУ балансоутримувача
- min_price, max_price - стартова ціна, грн
- area_unit (ha. або sq.m.), min_area, max_area - площа
- page, pagesize - номер сторінки та кількість на сторінці (до 100, типово 50)

У відповіді: itemsCount, pagesCount, page, pagesize, nextPageLink (адреса наступної сторінки або null) і data - список аукціонів з полями name, number, companyName, auctionStart, status, start_price_type, auction_type, price, balance_holder, url.
status - «Редагування доступне» (організатор ще може змінювати умови аукціону, прийом заяв почнеться після завершення цього періоду) або «Прийняття заяв на участь».
auctionStart - дата торгів; null, якщо етапу торгів немає (продаж без аукціону).
balance_holder - {"name": "...", "edrpou": "..."} або null, якщо балансоутримувача у аукціоні немає.
У посиланні url є мітка utm_source з назвою клієнта: telegram_prod (основний бот), telegram (тестовий бот) або infopilot.


5. Декілька регіонів

І в пошуку, і в моніторингах у region можна передати декілька регіонів одразу. Є два варіанти, працюють обидва:
- одним рядком через кому: region=Київ,Львівська область
- масивом: region[]=Київ&region[]=Львівська область (у JSON - "region": ["Київ", "Львівська область"])

Аукціон підходить, якщо він знаходиться хоча б в одному з вказаних регіонів.
У відповідях по моніторингах region завжди повертаєтсья рядком через кому.

6. Моніторинги

Обов'язкові поля - user_id та name (назва моніторингу), далі ті самі фільтри, що й у пошуку (крім page і pagesize). Потрібен хоча б один фільтр, на одного користувача - до 200 моніторингів.
Тільки для InfoPilot: поле webhook - адреса, на яку йтимуть повідомлення по цьому моніторингу (п. 7). Адреса повна, з https://, без параметрів (? і #) та пробілів, до 1000 символів, і тільки на домені infopilot.pro або його піддоменах (наприклад https://nika.infopilot.pro/thetender/webhook), інакше моніторинг не збережеться і в errors буде пояснення. Якщо webhook не вказано, повідомлення йдуть на загальну адресу клієнта (п. 8). У Telegram-ботів цього поля немає, адреса в них одна.
Дані можна передавати у JSON (Content-Type: application/json) або звичайною формою.
При зміні передаються всі поля, не передані - очищуються.
id в адресах update та delete - це id моніторингу (він приходить у відповіді на створення та у списку моніторингів).
У відповіді на створення та зміну: saved (true/false), errors, data. На видалення: deleted. Якщо моніторинг не знайдено або він належить іншому клієнту - 404.

Приклад створення:

POST /rest/monitoring/create
{
  "user_id": "nika-12",
  "name": "Продаж, Київ та область",
  "auction_type": "sale",
  "region": "Київ,Київська область",
  "webhook": "https://nika.infopilot.pro/thetender/webhook"
}

Відповідь:

{
  "saved": true,
  "errors": [],
  "data": {
    "id": 15,
    "user_id": "nika-12",
    "monitoring": {

Поле webhook є у відповідях тільки для InfoPilot. У такому ж вигляді (id, user_id, monitoring) моніторинги приходять і у списку GET /rest/monitoring?user_id=...


7. Вебхук про новий аукціон

Коли на майданчику з'являється новий аукціон, який підходить під моніторинги клієнта, ми відправляємо POST на адресу вебхука: <адреса>?auth=<ключ клієнта>, тіло у форматі JSON:

{
  "event_type": "new_auction",
  "event_id": 12345,
  "auction_data": { ... ті самі поля, що у пошуку ... },
  "users": [ { "<user_id>": "<назва моніторингу>" } ]
}

Вебхук відправляється одразу після публікації аукціону - тобто ще в статусі «Редагування доступне», якщо в аукціоні є такий період, а не після початку прийому заяв.
Вебхук приходить лише про аукціони, на які можна подати заяву: у статусі «Редагування доступне» або «Прийняття заяв на участь» і до завершення прийому заяв, у тому числі про продаж без аукціону.
На кожен аукціон - один запит на кожну адресу, у users перелічені тільки користувачі, у яких спрацював моніторинг з цією адресою. Якщо у користувача спрацювало кілька моніторингів, він буде у списку один раз.
У InfoPilot моніторинги з різними webhook отримують окремі запити: nika-12 з адресою nika.infopilot.pro і nika-test-3 з адресою nika-test.infopilot.pro отримають кожен свій запит.
Параметр auth - це ваш ключ, з яким ви звертаєтесь до API, по ньому варто перевіряти, що запит від нас.
Чекаємо відповідь 2xx протягом 10 секунд. Якщо відповіді немає або код інший - повторюємо: 3 спроби одна за одною, далі приблизно раз на 5 хвилин, доки не отримаємо 2xx. Через повтори той самий запит може прийти двічі, ДУблі відкидайте за event_id.
Якщо у моніторингу немає своєї адреси і загальна адреса клієнта не задана, запити по ньому не відправляються


8. Адреса вебхука

Загальну адресу кожен клієнт задає сам, зі своїм ключем. У Telegram-ботів це єдина адреса, у InfoPilot - адреса для моніторингів без свого webhook (можна не задавати, якщо webhook є в кожному моніторингу):

POST /rest/set_webhook
address=https://... (звичайною формою або JSON {"address": "https://..."})

Адреса повна, з https://, без параметрів (? і #) та пробілів, до 1000 символів, для InfoPilot - тільки на домені infopilot.pro або його піддоменах. Ключ ми додаємо самі (?auth=...).
Відповідь: {"saved": true, "address": "<збережена адреса>"}, при помилці - 400 з поясненням.
Нова адреса діє з наступної відправки.


9. Журнал відправок

Історію відправок видно в адмінці, розділ "Розсилки за моніторингами": по кожній події - канал (Viber, Telegram, Telegram тестовий бот, InfoPilot), стан доставки, адреса і код відповіді, є фільтри по каналу і стану доставки. Недоставлену подію можна відправити повторно вручну, вона піде на ту саму адресу.


10. Категорії

Список категорій однаковий для всіх клієнтів. Які категорії доступні, визначається в адмінці - галочка "Пошук у Viber/Telegram" у налаштуваннях категорії
