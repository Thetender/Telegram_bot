API майданчика The Tender для Telegram-бота
(оновлено 09.10.2026: п. 7 — повторні спроби вебхука кожні 300 секунд)

Telegram-бот працює з тим самим API, що і Viber-бот. Адреси та параметри запитів ті самі, відрізняється тільки ключ. Боти працюють паралельно і один одного не бачать, для Viber-бота нічого не змінилось.


1. Авторизація

У Telegram-бота свій ключ, окремий від Viber. Ключ передається параметром auth в адресі або заголовком Authorization. Без ключа чи з невірним ключем повертається 403. Відповіді у форматі JSON.
По ключу майданчик сам визначає, від якого бота прийшов запит, тому ніяких додаткових параметрів (тип бота і т.п.) передавати не треба.
Ключ Telegram можна змінити або відкликати, на Viber це не вплине.
Ключ передам окремо.

Базова адреса для тестуваня: https://sandbox.mxuser.com
Після тестування перенесемо на https://thetender.com.ua (ключ там буде інший).


2. Ендпоінти (ті самі, що у Viber)

GET     /rest/categories - список категорій для бота
GET     /rest/auctions - пошук аукціонів, на які зараз приймаються заяви
GET     /rest/monitoring?user_id=... - моніторинги користувача
POST    /rest/monitoring/create - створити моніторинг
PUT     /rest/monitoring/update?id=... - змінити моніторинг
DELETE  /rest/monitoring/delete?id=... - видалити моніторинг


3. Користувачі (user_id)

user_id - це Telegram id користувача (число, наприклад 123456789). Зберігаємо його рядком, до 255 символів.
Моніторинги Telegram і Viber зберігаються окремо. З ключем Telegram видно і можна змінювати тільки моніторинги Telegram, з ключем Viber - тільки моніторинги Viber. Якщо user_id у двох ботах випадково співпаде - це все одно різні користувачі.


4. Пошук аукціонів

Усі параметри необовязкові:
- auction_type - sale (продаж) або rent (оренда)
- start_price_type - eng (англійський аукціон) або hol (голландський)
- category - назва категорії
- region - регіон, один або декілька (див. п. 5)
- city - населений пункт
- keywords - ключові слова
- customer_name - назва або код організатора
- min_price, max_price - стартова ціна, грн
- area_unit (ha. або sq.m.), min_area, max_area - площа
- page, pagesize - номер сторінки та кількість на сторінці (до 100, типово 50)

У відповіді: itemsCount, pagesCount, page, pagesize, nextPageLink (адреса наступної сторінки) і data - список аукціонів з полями name, number, companyName, auctionStart, status, start_price_type, auction_type, price, url.
Посилання у полі url для Telegram-бота йдуть з міткою utm_source=telegram.


5. Декілька регіонів

І в пошуку, і в моніторингах у region можна передати декілька регіонів одразу. Є два варіанти, працюють обидва:
- одним рядком через кому: region=Київ,Львівська область
- масивом: region[]=Київ&region[]=Львівська область (у JSON - "region": ["Київ", "Львівська область"])

Аукціон підходить, якщо він знаходиться хоча б в одному з вказаних регіонів.
У відповідях по моніторингах region завжди повертаєтсья рядком через кому.

6. Моніторинги

Обов'язкові поля - user_id та name (назва моніторингу), далі ті самі фільтри, що й у пошуку. Потрібен хоча б один фільтр, на користувача - до 200 моніторингів.
Дані можна передавати у JSON (Content-Type: application/json) або звичайною формою.
При зміні передаються всі поля, не передані - очищуються.
id в адресах update та delete - це id моніторингу (він приходить у відповіді на створення та у списку моніторингів).
У відповіді на створення та зміну: saved (true/false), errors, data. На видалення: deleted. Якщо моніторинг не знайдено або він належить Viber-боту - 404.

Приклад створення:

POST /rest/monitoring/create
{
  "user_id": "123456789",
  "name": "Продаж, Київ та область",
  "auction_type": "sale",
  "region": "Київ,Київська область"
}

Відповідь:

{
  "saved": true,
  "errors": [],
  "data": {
    "id": 15,
    "user_id": "123456789",
    "monitoring": {
      "name": "Продаж, Київ та область",
      "auction_type": "sale",
      "start_price_type": null,
      "category": null,
      "region": "Київ,Київська область",
      "city": null,
      "keywords": null,
      "customer_name": null,
      "min_price": null,
      "max_price": null,
      "area_unit": null,
      "min_area": null,
      "max_area": null
    }
  }
}

У такому ж вигляді (id, user_id, monitoring) моніторинги приходять і у списку GET /rest/monitoring?user_id=...


7. Вебхук про новий аукціон

Для Telegram-бота зроблено окремий вебхук, вебхук Viber-бота не змінювався.
Коли на майданчику з'являється новий аукціон, який підходить під моніторинги Telegram, ми відправляємо POST на вашу адресу: <ваша адреса>?auth=<ключ Telegram-бота>, тіло у форматі JSON:

{
  "event_type": "new_auction",
  "auction_data": { ... ті самі поля, що у пошуку ... },
  "users": [ { "<user_id>": "<назва моніторингу>" } ]
}

На кожен аукціон - один запит, у users перелічені тільки користувачі Telegram, у яких спрацював моніторинг. Якщо у користувача спрацювало кілька моніторингів, він буде у списку один раз.
Чекаємо від вас відповідь 200 протягом 10 секунд.
Повторні спроби: якщо відповідь не отримано (таймаут, сервер недоступний або код не 2xx), майданчик зберігає подію і автоматично повторює відправку кожні 300 секунд, доки не отримає відповідь 2xx. Повторні спроби продовжуються і після перезапуску майданчика. При повторі надсилається той самий запит (ті самі auction_data та users). Ручного повторного надсилання (replay) немає.
Повторне отримання того самого аукціону для того самого користувача бот обробляє сам (дедуплікація), тому повтори безпечні.
Адресу вебхука чекаю від вас. Поки її немає, запити для Telegram не відправляються.
Історію відправок видно в адмінці, розділ "Статистика викликів ботів (Viber, Telegram)", там є фільтр по боту.


8. Категорії

Список категорій у Telegram-бота той самий, що й у Viber. Які категорії доступні ботам, визначається в адмінці - галочка "Пошук у Viber" у налаштуваннях категорії.
